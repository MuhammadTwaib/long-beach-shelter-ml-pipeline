# Code review checklist (Part C2)

Use this for every pull request. A reviewer ticks what they checked and leaves
comments that are **specific** ("line 42 drops rows without logging how many")
and **kind** (comment on the code, not the person). Mark small things as `nit:`
so the author knows they are optional.

## 1. Does it do the right thing?
- [ ] The PR description says what changed and why; the change matches it.
- [ ] I ran it (or CI ran it) and the output looks right, not just "no error".
- [ ] Edge cases: empty input, missing values, unknown categories, wrong file path.

## 2. Data & ML specific
- [ ] Raw data is not modified; new outputs go to `data/cleaned/` or `outputs/`.
- [ ] Any new feature is known **at intake time** (no leakage).
- [ ] Fitting (imputer, scaler, encoder, model) happens only on training data, inside the Pipeline.
- [ ] Test set is not used to choose models, thresholds or features.
- [ ] Metrics reported are the agreed ones (PR-AUC, recall, precision, F1), not accuracy alone.

## 3. Readability
- [ ] Names say what things are (`length_of_stay_days`, not `x2`).
- [ ] Every function has a docstring; comments explain *why*, not *what*.
- [ ] No dead code, no commented-out blocks, no debugging prints.
- [ ] File header (name, roll number, date) present on new `.py` files.

## 4. Tests & CI
- [ ] New or changed functions have at least one test, including a failure case.
- [ ] CI is green (lint + tests + smoke runs).

## 5. Safety & hygiene
- [ ] No secrets, tokens or personal data committed.
- [ ] Dependencies pinned in `requirements.txt` if a new one was added.
- [ ] Large generated files are either small enough for Git or regenerated by a script.

## What a good review looks like
* Reviewed within one working day; the PR is small enough to read in ~30 minutes.
* Starts with the big picture (design, correctness), then details.
* Asks questions instead of giving orders when unsure ("Could this double-count repeat intakes?").
* Approves when the code makes the project better, even if it is not perfect.
